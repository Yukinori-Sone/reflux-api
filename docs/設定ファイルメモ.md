# 設定ファイルメモ

Reflux（コア）の `config.ini` と関連ファイル、Reflux.Client の設定のまとめ。
コードで確認した内容（2026-06-18 時点、`MyCustom` ブランチ）。

## 共通の注意

- `config.ini` は **exe と同じフォルダ** に置く（実行フォルダ基準の相対パスで読む）
- **ビルドすると出力先の `config.ini` は `Reflux/config.ini`（リポジトリの原本）で上書きされる**
  （csproj で `CopyToOutputDirectory=Always`）。
  手元で試す設定は配布先フォルダ側で書き換えるか、原本を変えるならコミットに含めるか意識すること
- キーが無い／値が読めない場合
  - true/false の項目 → `false` 扱い（コンソールに `Couldn't read key ...` と表示される）
  - 文字列の項目 → 空文字扱い
  - `[Api]` セクションだけは例外で、無くてもメッセージを出さず既定値で動く（＝API 無効）
- 値の true/false は大文字小文字を区別しない（`True` / `true` どちらも可）

## config.ini

「初期値」はリポジトリ同梱の `config.ini` の値。

### [Update] 更新チェック

| キー | 初期値 | 意味 |
|---|---|---|
| `updateFiles` | `true` | ゲームのバージョンと `offsets.txt` が合わないとき、`updateserver` から新しい `offsets.txt` を取りに行くか。`false` だと取りに行かず、すぐ対話式のオフセット探索モードに入る |
| `updateserver` | `https://raw.githubusercontent.com/olji/Reflux/master/Reflux/` | サポートファイル（`offsets.txt` 等）の取得元 URL。本家リポジトリの master を直接見ている |

補足（設定に関係なく行われる通信）:

- 起動時に毎回 GitHub の本家リリースページを見て、新しいバージョンがあれば赤字で表示する
- アタッチのたびに `encodingfixes.txt` / `customtypes.txt` を `updateserver` と比べ、
  サーバー側の日付（1行目）が新しければ置き換える（旧ファイルは `archive/` へ）。
  **`updateFiles = false` でもこちらは止まらない**

### [Record] 記録の保存先

| キー | 初期値 | 意味 |
|---|---|---|
| `saveremote` | `false` | プレー結果・解禁状況を Reflux Server（`[RemoteRecord]`）へ送信する |
| `savelocal` | `true` | ローカル保存。下記をまとめて ON/OFF する（細かく分けられない点に注意） |
| `savejson` | `false` | セッションごとの JSON（`sessions/Session_日時.json`）に1プレーずつ追記 |
| `savelatestjson` | `true` | 直近1プレーを `latest.json` に上書き保存 |
| `savelatesttxt` | `true` | 直近1プレーを配信向けの txt 群に上書き保存（下表） |

`savelocal = true` で行われること:

- `sessions/Session_日時.tsv` を作り、プレーごとに1行追記（列は `[LocalRecord]` で決まる）
- プレーごとに自己ベスト（ランプ・DJ LEVEL・EX スコア・ミスカウント）を `tracker.db` に反映
- **選曲画面にいる間、2秒ごとに `tracker.tsv` を全件書き直す**（負荷が気になる点。削減は保留タスク）
- `saveremote` も ON なら `unlockdb`（解禁状態のキャッシュ）も保存。※ `savelocal = false` だと `unlockdb` も保存されない

`savelocal` に関係なく行われること:

- アタッチ時に、ゲーム内の自己ベストと `tracker.db` を突き合わせて `tracker.db` を書き直す

`savelatesttxt = true` で出力されるファイル:

| ファイル | 内容 |
|---|---|
| `latest.txt` | 英語曲名・DJ LEVEL・ランプ略号（`HC` 等）の3行 |
| `latest-titleenglish.txt` | 英語曲名 |
| `latest-grade.txt` | DJ LEVEL（`AAA` 等） |
| `latest-lamp.txt` | ランプ（`HARD CLEAR` 等） |
| `latest-difficulty.txt` | 難易度（`SPA` 等） |
| `latest-difficulty-color.txt` | 難易度の色コード（N 青 / H 橙 / A 赤） |

注意: `latest.json` には `[RemoteRecord]` の `apikey` がそのまま含まれる（本家の仕様）。
配信ソフト等で中身を公開する場合は気を付けること。

### [RemoteRecord] Reflux Server への送信

`saveremote = true` のときだけ使う。

| キー | 初期値 | 意味 |
|---|---|---|
| `serverAddress` | `https://server.here`（ダミー） | Reflux Server（https://github.com/olji/Reflux_Server）の URL |
| `apikey` | `apikey`（ダミー） | Reflux Server 用の API キー。下記 `[Api]` の `apikey` とは別物 |

### [LocalRecord] セッション TSV の列

`sessions/Session_日時.tsv` に出す列を選ぶ。曲名・難易度・playtype・DJ LEVEL・ランプ・ミスカウント・日時は常に出力される。

| キー | 初期値 | true で追加される列 |
|---|---|---|
| `songinfo` | `true` | 英語曲名(title2)、BPM、アーティスト、ジャンル |
| `chartdetails` | `true` | ノート数、レベル |
| `resultdetails` | `true` | ゲージ%、EX スコア |
| `judge` | `true` | PG / GR / GD / BD / PR / コンボブレイク / FAST / SLOW |
| `settings` | `true` | 譜面オプション(style)、DP 2P側オプション(style2)、ゲージ、アシスト、レーンカバー(range) |
| `uselocaltime` | `false` | 日時列を UTC ではなくローカル時刻（日本時間）で出す |

### [Livestream] 配信向けファイル

| キー | 初期値 | 意味 |
|---|---|---|
| `showplaystate` | `true` | `playstate.txt` に状態を書く: `menu`（選曲・リザルト）/ `play`（プレー中）/ `off`（INF 終了） |
| `enablemarquee` | `true` | `marquee.txt` に表示用テキストを書く（下記） |
| `enablefullsonginfo` | `true` | プレー中に `title.txt` / `artist.txt` / `englishtitle.txt` / `genre.txt` / `level.txt` / `folder.txt` を書き、選曲画面に戻ると空にする |
| `marqueeidletext` | `Beatmania IIDX Infinitas` | 選曲画面中に `marquee.txt` に出す文字列 |

`marquee.txt` の内容: 選曲画面 → `marqueeidletext` ／ プレー中 → 英語曲名（大文字）／
リザルト → `曲名 CLEAR!` または `曲名 FAIL!` ／ INF 終了 → `NO SIGNAL`

同梱の `SegmentDisplay 9 units / 16 units (browser source ...).html` は、`marquee.txt` を
OBS のブラウザソースで7セグ風に表示するためのもの。

### [Debug]

| キー | 初期値 | 意味 |
|---|---|---|
| `outputdb` | `false` | アタッチ時に曲リストを `songs.tsv` に出力（文字化け確認用） |

### [Api] 独自追加：別PCクライアント用 API

| キー | 初期値 | 意味 |
|---|---|---|
| `enabled` | `false` | HTTP API を起動するか。INF にアタッチしていなくても起動する |
| `host` | `localhost` | 待ち受けアドレス。`localhost` は同じPCからのみ。別PCから使うなら `+`（全インターフェース） |
| `port` | `8790` | 待ち受けポート |
| `apikey` | 空 | 設定すると、クライアントはヘッダー `X-Api-Key` に同じ値を付けないと拒否される。LAN 公開時は設定推奨 |

`host = +` にする場合の事前準備（ゲームPCで1回だけ、管理者権限で）:

```powershell
netsh http add urlacl url=http://+:8790/ user=<ゲームPCのユーザー名>
# ファイアウォールでポート 8790（TCP 受信）を許可
New-NetFirewallRule -DisplayName "Reflux API" -Direction Inbound -Protocol TCP -LocalPort 8790 -Action Allow -Profile Private
```

## サポートファイル（exe と同じフォルダ、同梱）

| ファイル | 中身 | 更新 |
|---|---|---|
| `offsets.txt` | 1行目: 対応するゲームのバージョン（`P2D:J:B:A:yyyymmddnn`）。以降: 各データのメモリアドレス | ゲーム更新でずれる。`updateFiles` が true なら自動取得、合わなければ対話式探索 |
| `encodingfixes.txt` | 1行目: 日付。以降: `化けた文字列<TAB>正しい文字列` | アタッチ時に自動更新 |
| `customtypes.txt` | 1行目: 日付。以降: `曲ID,ラベル`（楽曲パック `TRI3`、DJP 解禁 `800DJP` 等） | アタッチ時に自動更新 |
| `beginners.txt` | BEGINNER 譜面がある曲 ID の一覧 | 現在のコードからは参照されていない（同梱されているだけ） |

## 実行中に作られるファイル

| ファイル | 中身 |
|---|---|
| `tracker.db` | 自己ベストの保存（ゲームのメモリに無い PERFECT CLEAR などを保持）。消さないこと |
| `tracker.tsv` | 全譜面の自己ベスト・解禁状況（Mina's Unlock Tracker スプレッドシート互換） |
| `bestdetail.json` | 独自追加。自己ベスト時の判定内訳（PG/GR、BAD/POOR）。消さないこと |
| `sessions/` | セッションごとの TSV / JSON |
| `log.txt` | エラーログ（追記され続ける） |
| `archive/` | 更新で置き換えられた古いサポートファイル |
| `unlockdb` | `saveremote` 用の解禁状態キャッシュ |

## Reflux.Client（別PC側）の設定

exe と同じフォルダに作られる。

| ファイル | 中身 |
|---|---|
| `client.json` | 接続先。画面で「接続」を押すと保存される |
| `reflux-client.db` | SQLite。曲・譜面・スコア・シリーズ名・フォルダ定義。シリーズ名やフォルダの抽出条件はこの DB を直接編集して変えられる |

`client.json` の項目:

| キー | 初期値 | 意味 |
|---|---|---|
| `Host` | `localhost` | コア（ゲームPC）のホスト名／IP |
| `Port` | `8790` | コアの `[Api] port` と合わせる |
| `ApiKey` | 空 | コアの `[Api] apikey` と合わせる |
| `PollIntervalMs` | `2000` | 状態を問い合わせる間隔（ミリ秒、最小 500）。画面には無いので、変える場合はファイルを直接編集 |
